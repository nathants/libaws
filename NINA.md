# NINA.md

## Documentation

- `readme.md` is for humans: keep it concise and user-facing, in its established reference style (behavior, attributes/defaults, schema, example). `NINA.md` is for agents; keep essential implementation constraints and validation guidance here, not detailed run histories.
- Do not add new Markdown files unless Admin explicitly requests them. Put only terse, need-to-know project guidance in `NINA.md`.
- State general philosophy and tradeoffs once near the top. Feature sections should not repeat why libaws is opinionated, compare it with full-API tools, narrate implementation details, or include review history.
- Document externally relevant constraints without exhaustive internal safety proofs. Keep live-example links in the central examples list rather than repeating them in feature sections.

## Architecture and testing

- Prefer Spot EC2 instances for test fixtures when possible to reduce cost. On-demand instances are appropriate when needed, including tests of the on-demand launch path.
- `ec2-new` identifies NVMe instance store by its exact sysfs model, not device numbering or an instance-family list. Initialize the first model-matching instance-store whole device as ext4 at `/mnt`, refusing a disk that is already in use; preserve EBS, and reject partitions, signatures, mounts, holders, occupied/configured mountpoints, and failed safety reads before formatting.
- `EC2DeleteAmi` uses `DeregisterImage(DeleteAssociatedSnapshots=true)` so EC2 preserves shared snapshots at mutation time. Never infer backing snapshots from descriptions or replace this with a racy client-side scan/delete. Check every per-snapshot result. An AMI that exists under another owner is an error, not an absent no-op; only a confirmed-absent AMI is a no-op. `examples/misc/ec2-ami` tests previews, exclusive deletion, shared/decoy preservation, foreign-owner refusal, and idempotence without launching guests; cleanup discovers only its unique creation-time tags. Local regressions: `bash test_one.sh ec2_ami`.

- Build `infra.yaml` declarations around concrete project needs. Expose only the simple, opinionated subset of AWS behavior that we actually intend to use, add options only when a project needs them, and provide strong defaults for everything else. Do not mirror complete AWS service APIs; callers needing the full AWS configuration surface should use Terraform.
- Keep `cmd/` packages as thin CLI wrappers: parse arguments, translate them into `lib/` calls, and handle process I/O and fatal errors.
- Put behavior that should be unit- or integration-tested in `lib/`, with its tests under `lib/`. Do not add command-package tests to compensate for testable logic in `cmd/`; move that logic into `lib/` instead.
- The CLI wrappers are exercised through `examples/`, which invoke the built `libaws` command directly.
- CLI option spellings must be unique within each command, and `-p` is reserved for `--preview`: every preview flag keeps `-p`, and no other option may use it. `make check-cli-aliases` (included in `make check`) builds the CLI and checks every command's effective help for both rules. `examples/misc/ec2` checks both preview spellings and long-only `--private-ip` against owned AWS guests, recording transport locally with automatic termination disabled.
- Treat S3 keys as opaque strings: strip only a leading `s3://`, never clean dot segments, and trim display parents literally. `examples/misc/s3-keys` covers object/version commands, presigned requests, common prefixes, and recursive/start-after quiet output against real S3.
- `lib/s3_delete_test.go` waits for bucket-deletion metadata to converge using the SDK waiter before its final typed `NoSuchBucket` assertion; successful `DeleteBucket` is not immediate absence proof.
- `examples/misc/r2` is opt-in via `LIBAWS_R2_TEST_ACCOUNT`, which must match `R2_ACCOUNT_ID`; it also requires `R2_ACCESS_KEY_ID` and `R2_ACCESS_KEY_SECRET`. It creates only a unique `libaws-testing-<uuid>` bucket, proves initial/final absence, and uses independent SDK cleanup even if CLI operations fail. It never enumerates or mutates other buckets. Run it armed when changing R2 behavior; an AWS-only suite's explicit R2 skip is not provider acceptance.
- Docker is always rootless. Use the user's Docker daemon directly, never `sudo docker` or the system Docker service. Tests that replace `DOCKER_CONFIG` must preserve the active daemon endpoint first.
- Keep example dependencies exact and reproducible with the applicable committed `go.mod`/`go.sum`, `uv.lock`/exported requirements, or `pnpm-lock.yaml`; pin container images by digest. Safe-check each dependency root independently and use only dependencies and images that are at least 14 days old. Safe's module-wide GO-2026-5932 finding is accepted because libaws imports `x/crypto/ssh`, not the deprecated `openpgp` package; `govulncheck` must remain clear. `go.mod` must stay tidy, so keep vulnerable transitive versions out of the module graph with `exclude` directives rather than unneeded requirements.
- Python build isolation is part of the locked graph. Each Python project pins `tool.uv.build-constraint-dependencies` and a matching `build` dependency group; export it to `build-requirements.txt` with `uv export --locked --only-group build --no-header --no-annotate --no-hashes`. Lambda requirements pass that file using pip's `--build-constraint`. `test.sh` verifies both runtime/build exports before running examples; `lib/lambda_package_build_test.go` asserts the actual isolated backend version while testing byte reproducibility. Do not disable build isolation or rely on a warm wheel cache to prove pins.
- `shell.run` normally returns only stdout; preview acceptance must capture stderr and check exit status explicitly. The Python dependencies example verifies unchanged/changed/restored package previews using a temporary source copy; its nonlive regression exercises real py-shell stream handling.
- Admin owns and trusts dependencies under `github.com/nathants`; ignore their provenance/provider warnings, but keep exact commit pins. This exception does not cover their third-party dependencies. When Safe cannot parse Git-bearing uv locks, scan an exact PyPI requirements manifest derived independently from each lock's complete registry graph (including dev/transitive packages), and scan local packages' build requirements separately. Exclude only the trusted Git nodes and project-local sources, not whole dependency roots. List exactly that set in each Python project's `tool.uv.no-binary-package` so it builds under a user-level uv `no-build = true`; never list third-party packages.
- Every behavior change must have a permanent integration test or example that exercises the actual behavior against real AWS. Unit tests supplement rather than replace this acceptance coverage.
- Ensure previews may tolerate a genuinely absent new resource, not permission or configuration-read failures. `lib/preview_reads_test.go` verifies real AWS denial responses using a unique role with no permissions; only the current caller may assume it.
- `LogsRecent` accepts 1–10000 lines, matching CloudWatch's per-request limit. Validate all stream names before starting its bounded workers; no error path may return with requests still running. `lib/logs_test.go` covers the limit against AWS and malformed metadata with a bounded worker-lifecycle regression.
- Every `infra.yaml` schema or semantic change must be documented in `readme.md` and exercised by a checked-in `examples/` infrastructure declaration and its live AWS test.
- S3/SQS trigger sources are validated in `InfraParse` and the exported ensure helpers before provider calls. S3 permits exactly one bucket name; SQS requires the queue name before options. `examples/misc/trigger-validation` checks invalid CLI declarations and real named-resource absence before cleanup.
- DynamoDB TTL is a separate update after table creation reaches `ACTIVE`; the first ensure must apply it. Creation uses the SDK waiter with a five-minute bound and two-second polling, tolerating transient `ResourceNotFoundException` metadata reads without hiding other errors or cancellation. Assert TTL before any re-ensure in live coverage. Tables without declared TTL need no additional creation wait.
- SQS mapping re-ensure waits for existing mappings to settle and compares the refreshed configuration before updating; a mapping deleted while settling is recreated. Previews remain read-only and do not wait. `examples/simple/go/sqs` re-ensures immediately after creation, before inventory or fixture waiters, then covers disabled-mapping previews and re-enabling against AWS.
- `examples/misc/dynamodb-indexes` covers index throughput/projections and exact-number CLI get/scan results, including 38-digit precision, exponent boundaries, real pagination, and total limits. Retry fixture visibility only, never precision or pagination assertions.
- DynamoDB mapping previews inspect resolved streams even when other tables are new. Do not infer removals for unresolved declared tables; all-unresolved previews still avoid Lambda reads. `examples/simple/go/dynamodb/preview.yaml` covers mixed-preview immutable starting positions.
- Lambda environment validation has two distinct limits: 4096 bytes for AWS's compact JSON environment representation and 5120 bytes for the SDK-encoded configuration update. AWS counts U+2028/U+2029 as UTF-8, while Smithy escapes them and uses longer backspace/form-feed escapes. Keep the update-size check aligned with the fields actually sent; `examples/misc/basic` runs `lib/lambda_environment_live_test.go` against its owned fixture and covers CLI create/preview/full/quick paths.
- Full Lambda ensure resolves API identities and adds inline/managed role grants before code activation, preserving prior grants on failure and pruning only afterward. Never use the pruning public IAM owners for a partial pre-activation policy. `make check-lambda-iam` exercises actual SDK ordering/failure boundaries; `bash test_one.sh lambda_iam_live` verifies them against an isolated real Lambda, WebSocket API and role in the explicitly selected `LIBAWS_TEST_ACCOUNT`, including independent cleanup. This is API-ordering evidence, not universal IAM propagation or old-invocation drainage. Quick deployments require already-installed infrastructure prerequisites.
- `infra-ensure --build-only` compiles Go Lambda artifacts without AWS access; `--from-build` deploys only hash-verified artifacts, verifying every selected one before any provider call and never reading entrypoint sources. Python and container Lambdas keep their existing packaging. `examples/misc/lambda-build` covers the CLI directory contract, tamper rejection without AWS mutation, and a live source-free deploy; local regressions: `bash test_one.sh infra_build`.
- Live DNS/domain examples use `LIBAWS_TEST_DOMAIN`, which names a permanent, publicly delegated Route53 zone in the selected account. Tests automatically ensure and preserve its issued regional wildcard ACM certificate, DNS validation record, and untagged, unmapped `acm-fixture.${LIBAWS_TEST_DOMAIN}` API Gateway custom domain. The domain uses that certificate but has no Route53 record; the association keeps the certificate eligible for managed renewal. Tests may create and remove only unique child resources outside these fixtures.
- Whole API-domain/DNS cleanup requires `API_MAPPING_ONLY` plus verified exclusive ownership. Other or missing routing modes preserve the domain and DNS, deleting only mappings to the owned API. The API-domain example covers real routing-mode transitions after removing its HTTP mapping; it does not create REST routing rules.
- Test prerequisites are Go 1.27+, Python 3.12+, uv, rootless Docker, and `libcheck` on `PATH`. `make test` restores the locked Python environment with `restore_python_deps.sh`, then runs `bash test.sh`.
- `make check` runs `libcheck check` (the shared Go lint policy) and `libcheck security` (govulncheck), plus the CLI alias and Lambda IAM checks. Suppress a finding only when it is wrong for that line, with `//nolint:LINTER // reason`. `libcheck.json` disables deadcode because `lib` is a public Go API whose callers deadcode cannot see.
- `bash test.sh` runs checks/build, then `test_runner.py` discovers every example and eligible Go test file. Python examples use `uv run --locked`; `test_one.sh` compiles each Go file in isolation with `lib/lib_test.go` and the build-eligible non-test sources, using a unique binary path. All Go `_test.go` files live under `lib/`; shared helpers belong in `lib/lib_test.go`. The runner prepends the checkout to `PATH`; do the same before running an example directly so it exercises the newly built CLI.
- Inventory: `infra-ls --infraset NAME`/`InfraListSet` selects exact `libaws.infraset` tags, not resource-name substrings. Discover names/tags account-wide if necessary, but hydrate only selected resources. Paginate and reuse verified membership, including truncated IAM pages; reject broken cursors. Account-wide inventory must still inspect unrelated configuration.
- Inventory may omit disappearance only before ownership is established; later disappearance and read failures are errors, not empty results. Return complete API identities or an error. Only incomplete metadata gets bounded outer retries; provider errors propagate. Propagate worker errors and join/drain all workers and trigger producers before returning.
- Reconstruct triggers from verified relationships, never names. Scoped sources must belong to the selected set; Lambda targets must be unqualified and in the current partition/account/region. APIs require matching protocol and one `AWS_PROXY` integration across all pages. Reject multiple EventBridge targets and unrepresentable S3 notifications; retain unrelated resources as standalone roots.
- Scope SES candidates through exact receipt-rule ARNs in Lambda grants, then verify actions/recipients; reject unscopable grants. Shared DNS zones/certificates remain references; only same-set domains supply mappings, with DNS reads restricted to recorded zone/name.
- S3 inventory supports only no lifecycle or one enabled bucket-wide positive-day expiration. Use `Filter`, not legacy `Prefix`; reject other forms rather than guessing TTL. Verify actual root absence, not tag disappearance; SQS deletion can take 60 seconds. Wait for fixture visibility, never retry failed inventory assertions.
- Inventory checks: `bash test_one.sh infra_list`, `bash test_one.sh infra_s3_race`; live coverage is `examples/misc/infrasets` through `bash test.sh`.
- Live examples use unique resource names. Teardown must be registered before provisioning, run on failure, and attempt every cleanup even if another fails. `examples/simple/python/ecr` and `examples/misc/cleanup` cover partial creates, post-create inventory errors, login/push/build failures, failed cleanup actions, and live AWS failure paths. Alarm, SES, and basic examples register independent root/trigger/local finalizers; their live cleanup cases inject primary teardown failure after successful AWS provisioning. Verify declared roots, untagged ECR repositories, and unique local image tags independently of infrastructure-set inventory.
- ECR events are best-effort AWS delivery. The Go/Python/Docker ECR examples require their own pushed image event and bound `logs-tail` to 180 seconds, leaving time for independent finalizers before the runner's hard timeout. A missing event remains a failure, never substituted with another fixture's event.
- EC2 examples share keypair-scoped compute cleanup in `lib/lib_test.go`: cancel pending fleets, terminate instances, and verify their states independently of infrastructure membership. `examples/misc/ec2` removes its VPC and keypair independently even if another cleanup fails. The S3→EC2 finalizer in `lib/s3_ec2_example_test.go` first stops the Lambda and drains its configured timeout if an S3 event might have been sent; deleting the Lambda does not stop an in-flight invocation. Pending fleets are not infrastructure-set members.
- SES and EventBridge rollback use fresh one-minute contexts after caller cancellation and preserve both primary and restoration errors. `lib/rollback_live_test.go` cancels after real AWS mutations; active SES restoration runs only inside the exclusive SES example, while its standalone empty-set test never activates a rule set.
- `LIBAWS_TEST_JOBS` controls the bounded pool (default 4). `lib/s3_test.go` deliberately validates account-wide S3 drift; the SES example and its live cleanup case change the single active receipt-rule set. The runner executes all three exclusively before the shared pool. The cleanup example's other live cases are separate jobs in that pool, each with its own process and unchanged 1800-second timeout; keep all nonlive cases in its `::nonlive` job. Do not add nested concurrency or duplicate `LIVE_EXAMPLES` in the runner. Do not overlap live suites in one scratch account.
- `test_runner.py` prints each test's path, status, duration, and retained log path. Per-test logs and `timings.tsv` (test, seconds, status) remain in the printed private temporary directory. SIGINT/SIGTERM stops new tests and drains started tests, allowing their cleanup to finish.
- Compare test performance with matched coverage, dependencies, and concurrency; measure wall time including setup/cleanup, not summed worker time. Regional EC2 improved one API-heavy example, but full-suite EC2 speedup remains unmeasured.
- EC2 `--init` runs as the image's login user, not root; use explicit `sudo` for privileged guest setup. `examples/complex/s3-ec2` demonstrates small Debian Spot guests with S3 input/output and automatic poweroff. `examples/misc/ec2` verifies Spot/on-demand CLI launches and fleet failure teardown against AWS, using guests without ingress or instance credentials; its cleanup job uses a zero-capacity fleet to cover an accepted request with no instance ID and no risk of late guest launches. It also checks `ec2-scp`/`ec2-rsync` failure exits against an owned guest with its user tag removed: missing-user top-level errors and invalid-path per-host errors, not successful SSH transfers.
- Spot Fleet cancellation must check per-fleet results, not just HTTP success. Teardown tracks instances before/after cancellation and waits for their termination, not eventual `cancelled_*` fleet bookkeeping. Every failure after fleet creation uses a fresh, bounded five-minute cleanup context and retains both launch and cleanup errors; callers that kill interrupted processes must allow that cleanup window. Spot Fleet validity timestamps must use whole seconds; AWS rejects fractional seconds.
- `EC2WaitGoSsh` validates selectors, user, and private key before AWS reads. Literal instance IDs remain authoritative; retry initially missing IDs for up to 15 seconds without probing or pruning a partial set. Other selectors resolve one pending/running snapshot. Membership may shrink only for confirmed `shutting-down`/`terminated` IDs, never grow; terminal guests must not discard healthy survivors or cause an empty query. Prune only complete per-host SSH failures by ID, never re-resolved addresses. Failed lookups, malformed results, and caller cancellation must not prune. Return ready IDs. `lib/ec2_wait_gossh_test.go` covers these boundaries; `examples/misc/ec2` verifies real AWS pruning, terminal transitions, and survivors with no ingress. It injects SSH readiness results and one incomplete initial read, while also exercising a real SSH connection failure.
- `restore_python_deps.sh` materializes the virtualenv interpreter and its aliases. Keep `pyvenv.cfg` pointing to the real base installation; uv-managed Python aliases and a `python3 -> python` symlink into a copied interpreter can otherwise lose the standard library.
